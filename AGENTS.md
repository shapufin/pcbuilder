## Gotchas (learned the hard way — do not rediscover)

- **PowerShell quoting**: never inline JSON/quotes in `curl --data` from PS. Write JSON to a file and use `curl.exe --data @file`; use `[System.IO.File]::WriteAllText` for exact unicode. `curl -o $null` still dumps the body to the PS stream — use a real temp file (`C:\Users\EDEMNUSHIW\AppData\Local\Temp\opencode\`). Take strings for `Edit` oldString from the `Read` tool (real unicode), not PS console output (mojibake `—`/`€`). Also: in PS single-quoted strings `` `n `` is **literal backtick-n**, not a newline — a `.Replace(old, 'x`ny')` wrote broken JSON into package.json (entry 19); validate JSON with `ConvertFrom-Json` after scripted edits, or use the Edit tool. Also: `Select-Object -First N` closes the pipeline and **kills the upstream native process** (truncated output ⇒ false "exit -1/failed" — capture long command output to a file, then grep it).
- **turbo strict env mode**: shell-injected env vars (`set STRIPE_KEY=…&& pnpm dev`) are *stripped* from `pnpm dev` tasks. Put keys in `.env` (child loads it) or `pnpm dev --env-mode=loose`. `pnpm start` from `apps/web` bypasses turbo and inherits env. **Strict mode also strips vars from task *runs* unless the task declares them** — `turbo.json` now has `env` allowlists on `build` (DATABASE_URI, PAYLOAD_SECRET, BMR_URL, NEXT_PUBLIC_*) and `dev` (+ Resend/Stripe/staff-alert keys); **a new env var must be added there or the task cannot see it** (entry 24: CI build was silently hitting an empty sqlite file over this).
- **Stripe webhook**: route `POST /api/payments/stripe/webhooks` exists **only when `STRIPE_SECRET_KEY` is set** (404 is correct keyless). The `transactions` schema conditionally gains `paymentMethod` + `stripe` columns when an adapter exists — dev push self-heals on first key-ful boot; production must migrate *before* setting keys. Handlers live in `packages/plugin-shop/src/payments/stripe-webhooks.ts` (CAS-idempotent; deviate-from-plan event-id store intentionally).
- **CSRF**: cookie-authed requests need `Origin: http://localhost:3000` (allowlist: `BMR_URL` + localhost; `BMR_URL` must be set in prod). Note `BMR_URL` trailing slashes are normalized. This applies to **GETs too** — a REST GET with a session cookie and no Origin returns `200 {user:null}`/401 that looks like an auth failure (browsers are fine; curl/scripts must send the header).
- **New admin components** (`components.views`/`afterNavLinks`): run `pnpm payload -- generate:importmap` (dev server stopped) or the route 500s on the missing specifier.
- **pnpm 12** ignores `pnpm.overrides` in package.json → overrides live in `pnpm-workspace.yaml` (esbuild `0.18.20 → 0.25.12` **and** `undici: ^7.29.1` must survive upgrades — the latter is what makes `pnpm audit --audit-level high` pass in CI, entry 24).
- **Next peer windows are narrow**: payload 3.90.2 wants `>=15.4.11 <15.5.0 || >=16.3.3 <17.0.0` — check `@payloadcms/next` peers before any next bump.
- **SQLite push races**: `push: true` is not idempotent under concurrent pushes (dev server + `payload run`) — never run both. **`push` runs on dev boots only** — adding a collection/global/**block** and running only `pnpm build`/`pnpm start` leaves the table missing (prod `find` then 500s `no such table`, entries 18 and 22 — a nested block creates its own table, e.g. `pages_blocks_section`; the app-level fallback hid the entry-18 case). Boot `pnpm dev` once (watch for "Pulling schema from database…") after any schema addition, then switch back to prod.
- **Payload globals REST update is `POST /api/globals/:slug`, not PATCH** (`payload/dist/globals/endpoints/index.js` — updateHandler is `method: 'post'`; PATCH → 404). And in PowerShell, carry the login session with `-SessionVariable sv`/`-WebSession $sv` — a manually assembled `Cookie:` header from the login response arrives broken (`user:null`/403, entry 18). **Group data merges**: `{"colors":{}}` is a no-op — clear a field with explicit `""`/`null` (entry 21). Field validators see *omitted* group fields as empty on partial updates — optional-by-design fields must accept empty (entry 21 `optionalField` bug). Theme edits appear on cached routes after the ISR window (`/` = 60 s; first fetch after expiry can serve stale-while-revalidate). Also: payload **collection** REST create/update responses wrap the document in `{ doc }` (globals return it flat) — probes reading `res.id` straight get `$null` (entry 21).
- **Dev server restarts**: kill all `node` before `pnpm build`, then relaunch dev via the background cmd pattern; keep `dev-server.log` fresh for diagnosis.
- Build must be re-run after any server/route change (prod serves `.next`; the webhook e2e required a fresh build + a key-ful server).
- SVG uploads are banned (stored-XSS); rate limits are in-memory single-instance (deviation from the Upstash plan, documented).
- **IP-keyed rate limits trust the leftmost `X-Forwarded-For`** — client-controlled when the origin is reached directly; production must sit behind a proxy that overwrites `X-Forwarded-For`/`X-Real-IP` (entry-15 security review VULN-01; contract in `11-access-security.md`). Login brute-force is separately protected by payload `maxLoginAttempts: 5`.
- **build-templates store a SINGULAR `component` per slot; configured-builds use `components[]`** — mixing the two shapes silently produced empty price-0 builds (entry-15 bug #91/92; the endpoint now accepts both and 400s empty).
- **Playwright browsers are preinstalled** in `%LOCALAPPDATA%\ms-playwright` (chromium etc.) — do not reinstall or assume "no browser". `pnpm test:e2e` needs a fresh `pnpm build` + running `next start` (the config reuses an existing :3000 server); the register spec performs exactly **one** registration per run (5/min/IP limiter).
- **`vitest run` in apps/web picks up `e2e/*.spec.ts`** (Playwright files) without `apps/web/vitest.config.ts`, which scopes unit tests to `src/**` — keep that config when adding tests.
- **`seed-pages` is idempotent-by-slug and skips existing pages** — editing seeded homepage content in code won't update an existing dev DB (entry 16 patched the home CTA via admin REST `PATCH /api/pages/1`); only a fresh DB picks the new seed text.
- **payload `RichText` converters must be passed as a FUNCTION** (`({ defaultConverters }) => ({ ...defaultConverters, ... })`) — a plain converters *object* silently replaces `defaultJSXConverters`, and every paragraph/heading renders as "unknown node" (entry-22 review F1; regression test #155; wrapper = `lexicalRichTextConverters` in `apps/web/src/blocks/lexical-converters.tsx`).
- **`BlockSlug` is `string[]` inside plugin packages but a generated union in apps/web** (augmented `Config.blocks`) — slug arrays crossing that boundary need `as never` at the field (`blockReferences`/`filterOptions`), entries 22.
- **`pnpm start` / `next start` does NOT load the repo-root `.env`** (turbo children do; Next only auto-loads absent `apps/web/.env*`) — export the env in the launching shell, or root-level fallbacks (`DATABASE_URI file:./payload.db`, default `PAYLOAD_SECRET`) silently mask it (entry 23: contact probe hit the no-recipient path until `STAFF_ALERT_EMAIL` was exported in the same command). `payload run` reads shell `$env:`.
- **zustand v5 `getServerSnapshot` returns `getInitialState()`** — a `setState` made before `renderToStaticMarkup` is invisible to the render (entry 23: CartDrawer tests). Split the store-gated wrapper from the presentational component and render the presentational one with props for render assertions.
- **`apps/web` cart consumers must not trust `useEcommerce().cartID`** — the plugin's context value omits it (review F2, entry 23) and its base cart query is `depth: 0` with populate inert (F1): derive ids from `cart.id` / `localStorage('cart')`, and titles need `EcommerceShell`'s `api.cartsFetchQuery {depth:1, populate.products.title}`. New cart UI should reuse both. 
- **apps/web vitest needs the `@` alias** — `apps/web/vitest.config.ts` sets `resolve.alias {'@': …}` (entry 23); remove it and any `@/…` import fails resolution. **#140 was structurally fixed at entry 24** (the old cold-ESLint 30 s flake is gone): the hex-rule test imports shared `apps/web/eslint-rules/no-raw-hex.mjs` and runs a minimal ESLint (`overrideConfigFile: true`) in ~60 ms — do not re-add a full-config boot to that test; `#140c` pins the `eslint.config.mjs` wiring + test-file exemption.
- **Stray files in root `node_modules` mask undeclared deps** — a plain-directory `node_modules/react` + `@types/react` hid `plugin-pc-builder`'s missing react/next devDeps for weeks; only CI's strict install caught it (entry 24). Treat CI as the dependency-layout arbiter; don't restore strays when they turn up.
